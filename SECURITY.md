# Эксплуатационная безопасность

## Обязательные настройки

- Сгенерируйте отдельный случайный секрет для каждого пользователя: `openssl rand -hex 16`.
- Используйте порт 443 и реальный TLS 1.3 `mask_host`, отвечающий по HTTPS.
- Для наименьшего числа открытых режимов отключите обычный `dd` и оставьте только fake-TLS (`enable_secure: false`).
- Не используйте `ignore_time_skew: true` без отдельной причины: это ослабляет защиту от replay.
- Ограничьте доступ к файлу конфигурации и не записывайте Telegram-ссылки в общие логи.

## Что ядро не скрывает

- IP-адрес сервера, объём и временные характеристики трафика.
- Блокировку по IP/домену, маршрутизации или результатам активного подключения к Telegram.
- Несовпадение формы TLS-ответа с выбранным mask-host, если он ведёт себя иначе.

Ядро не содержит обещания «невозможности заблокировать». Устойчивость нужно проверять на конкретной сети и обновлять протокол при изменении Telegram-клиентов.

## Текущие границы

- Нет middle-proxy/ad-tag режима и автоматической ротации egress IP.
- Длина fake-certificate выбирается случайно при старте или задаётся вручную; автоматического измерения mask-host пока нет.
- Не проведена production-аттестация сторонним специалистом по MTProto или DPI.
